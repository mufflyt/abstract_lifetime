# Data Inventory

Machine-readable form: [`data_inventory.csv`](data_inventory.csv) — 70 files,
with producer, consumers, grain, primary key, row and column counts, git status,
reproducibility, external dependency and authority.

Counts were read from the files on 2026-09-03 at commit `665c551`. Caches with
thousands of small files (`data/cache/sd_html/`, `pubmed_xml/`, `orcid/`, …) are
described in aggregate below rather than enumerated row by row.

---

## 1. How to read the `type` column

| type | Meaning |
|---|---|
| `raw` | First materialisation of an external source inside the repository. |
| `intermediate` | Produced by one pipeline stage, consumed by another. |
| `cache` | Exists only to avoid re-hitting an API. Deletable; the pipeline will refetch. |
| `manual` | Contains human judgement that cannot be regenerated by running code. |
| `final` | Terminal output: analysis results, models, tables, figure data. |
| `documentation` | Written to be read, not consumed. |
| `legacy` | Superseded; retained only as a record. |

**Checkpoint semantics are resume-only, not invalidate-on-change.** Each search
script skips any `abstract_id` already in `completed_ids`. Editing a search
strategy does **not** invalidate the checkpoint; the edited strategy will never
run for an already-completed abstract until the RDS is deleted by hand. The
35 MB `pubmed_search_checkpoint.rds` is the reason the April 2026 matching
corrections required a full manual cache wipe.
