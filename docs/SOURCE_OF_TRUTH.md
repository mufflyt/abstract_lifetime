# Source of Truth

For every important entity: which file is authoritative, and why. If two files
disagree, the file named here wins.

---

## The rules

| Entity | Authoritative file | If two files disagree, THIS is authoritative because… |
|---|---|---|
| **Parsed presentations** | `data/processed/abstracts_parsed_web.csv` | It is what `R/01b_parse_web.R` writes first; `abstracts_parsed.csv` is a byte-identical copy made only so `02` can read a source-agnostic name. Where they differ, one of the in-place patchers (`01d`) has run on one and not the other. |
| **The cohort** | `data/processed/abstracts_cleaned.csv` | It is the only file where the video exclusion is applied, and every downstream row count is a function of its 1,106 `abstract_id` values. Its `abstract_id` set is a hard invariant asserted by `tests/testthat/test-pipeline_semantics.R:276`. |
| **Publication candidates** | `data/processed/match_scores_detailed.rds` | **Not** `pubmed_candidates.csv`. The RDS holds all 64,718 (abstract × candidate) pairs that were actually scored; the CSV on disk holds 48,984 rows, is missing 283 of the 1,102 winning PMIDs, and contains 610 `abstract_id`s from a superseded ID scheme. The CSV was rewritten by a later `03b` run than the one `04` scored against. |
| **Scored candidates and classification** | `data/processed/match_scores.csv` | `04_score_matches.R` is the only writer. `classification`, `best_pmid`, `best_score`, `has_tie` and `n_candidates` originate here and are copied — never recomputed — downstream. |
| **Human adjudication** | The **Google Sheet** `1d2YAsndMxCPK0AQMHw4bgKp3glFg_znGj8Riq5YpfaI`, worksheet `decisions` | It is where the Shiny app appends. `output/manual_review_decisions.csv` is a manual export; `app.R:1760` also writes it, but on shinyapps.io that write lands in an ephemeral container. For any *offline* analysis the CSV in the tree is authoritative, because it is what `06_analyze_results.R` reads. |
| **Deduplicated decisions** | `dedup_decisions_for_analysis()` in `R/utils_decisions.R` | The raw log has 1–10 rows per abstract. Three different dedup implementations exist (`utils_decisions.R`, the inline versions in `07_make_tables.R:21-26` and `08_make_figures.R:26-30`, and `dedup_decisions()` in the Shiny app). Only `utils_decisions.R` applies the human-outranks-AUTO precedence rule, and only it is covered by boundary and mutation tests. |
| **Final publication classification** | `final_published` in `output/final_analytical_dataset.csv` | Produced by `assign_final_published()`. `07` and `08` re-derive their own copy; they currently agree on all 1,106 rows but are not guaranteed to. |
| **Author demographics** | `output/abstracts_with_matches.csv` after `10e_merge_demographics.R` has run | `10e` is the only script that resolves the ten-tier gender waterfall and joins the NPI and ORCID sidecars. The sidecar CSVs in `data/processed/` are inputs, not answers. |
| **Final analytical dataset** | `output/final_analytical_dataset.csv` | Written once, at `R/06_analyze_results.R:43`, before any analysis. It is `abstracts_with_matches.csv` plus `manual_decision`, `manual_pmid`, `final_published`, `final_pmid`. |
| **Model outputs** | `data/processed/{km_fit,cox_model,logistic_model}.rds` | The `.rds` objects carry the formula and the fitted data; the `aim*.csv` files are `broom::tidy()` renderings and can be regenerated from them. Where a CSV and an RDS disagree, refit from the RDS. |
| **Manuscript tables** | `output/tables/table1`–`table4` | Generated by `07_make_tables.R`. Gitignored, so a fresh checkout has none. |
| **Cohort figure** | `output/figures/figure1_strobe_flowchart.{png,pdf}` | `R/strobe_flowchart.R` derives every count from the pipeline files and asserts the arithmetic with `stopifnot()` before drawing. `figure1_flow_diagram.png` (from `08_make_figures.R`) is also current but has no such assertion; `strobe_flow.{png,pdf,svg}` is from the superseded `strobe_flow_diagram.R`. |
| **Documentation metadata** | `docs/_meta/data_inventory_meta.csv` and `docs/_meta/data_dictionary_meta.csv` | The hand-authored half. `docs/data_inventory.csv` and `docs/data_dictionary.csv` are **generated** by `scripts/build_docs_metadata.R` and must never be edited directly — an edit there is overwritten on the next run, and the script fails if the metadata and the tree disagree. |
| **Pipeline parameters** | `config.yml` | Single source for congress dates, search windows, scoring thresholds, the Google Sheet ID and the checkpoint directory. `cfg$conference` is a back-compat block for legacy scripts and duplicates the 2023 entry. |
| **Congress dates** | `conference_date_for()` in `R/utils_congresses.R`, reading `config.yml` | No date is hard-coded anywhere else. `tests/testthat/test-cycle01_thresholds_contracts.R:175` asserts every congress year in the cohort has a config date. |

## Where the same logic is implemented more than once

Each of these is a place where two implementations can silently diverge.

| Logic | Canonical | Duplicates | Currently agree? |
|---|---|---|---|
| Decision deduplication | `dedup_decisions_for_analysis()` | `R/07_make_tables.R:21-26`, `R/08_make_figures.R:26-30`, `dedup_decisions()` in `app.R:268` | ✅ verified on all 1,106 rows — but the duplicates lack the human-over-AUTO rule and would diverge if `prefill_algorithm_decisions.R` were re-run after human review |
| `final_published` assignment | `assign_final_published()` | `R/07_make_tables.R:29-35`, `R/08_make_figures.R:34-42` | ✅ identical `case_when` |
| JMIG supplement detection | `is_supplement_article()` | `R/03b_search_crossref.R:292-297, 336-341` (journal+vol+year only), `search_europmc()` in `R/utils_crossref.R:553-556` (drops *all* JMIG) | ❌ the duplicates use the pre-April-2026 rule |
| Study-design classification | `classify_study_design()` in `R/utils_classify.R` | the inline `case_when` in `R/02_clean_abstracts.R:186-207` | ⚠️ the inline version is what runs; the function is what the tests cover |
| Research category / primary procedure | `classify_research_category()`, `classify_primary_procedure()` | inline `case_when` in `02_clean_abstracts.R:241-265` | ⚠️ same |
| Cohort flow diagram | `R/strobe_flowchart.R` | `R/strobe_flow_diagram.R`, the flow block in `08_make_figures.R` | ✅ same counts today |
| Shiny deployment | `shiny/adjudication_app/deploy.R` | `deploy_shiny.R` at the repository root | — `00_run_all.R:169` calls the former |

The `utils_classify.R` case is worth stating plainly: **the classifier functions
that the test suite exercises are not the code that produced the data.**
`02_clean_abstracts.R` inlines its own `case_when` chains. They were written to
match, and spot checks agree, but `tests/testthat/test-utils_classify.R`'s 32
tests protect the library copy, not the pipeline.

## Writers of `output/abstracts_with_matches.csv`

This file is an accumulator that six pieces of code rewrite in place, so its
contents depend on execution order:

| Order in `00_run_all.R` | Writer | Adds |
|---|---|---|
| Step 1d | `R/01d_tag_session_type.R:132` | `session_type` |
| Step 5 | `R/05_adjudicate.R:117` | **creates the file** — 45 columns |
| Step 5b | `R/09b_enrich_pub_types.R:81` | `pub_types`, `pub_type_canonical` |
| Step 5e | `R/09d_enrich_metrics.R:108` | `cited_by_count`, `journal_impact_proxy` |
| Step 5g | `R/09e_enrich_orcid.R:284` | the eight `orcid_*` columns |
| Step 5h7 | inline block, `00_run_all.R:127-146` | consolidates `first_author_first` |
| **not called by `00_run_all.R`** | `R/10e_merge_demographics.R:445` | gender waterfall, NPI, unified state/subspecialty |

`R/05_adjudicate.R` **recreates** the file from scratch. Running step 5 after
the enrichment steps therefore destroys every enrichment column. The
`NEWS.md`/`CHANGELOG.md` claim that `10e` is the "sole writer" is not correct.

author.

  both the `.Rmd` and the data.

- `data/processed/pubmed_strategy_results.csv` and
  `output/search_strategy_efficacy.csv` — rebuilt by the same run.

  `abstracts_with_matches.csv` so the block runs again, or remove the file and
  the block together.

  commit the audit script that produced it or remove the file. (The comparable
  gap for `data_inventory.csv`, `data_dictionary.csv` and the cohort-truncation
  audit was closed on 2026-09-04 by `scripts/build_docs_metadata.R` and
  `scripts/audit_cohort_completeness.R`.)
- `data/processed/second_author_triangulation.csv` and
  `R/10g_second_author_triangulation.R` — tier 9 of the gender waterfall never
  fires.
- `data/cache/jmig_2017_abstracts.json` — 97 rows of `null`.

**Never commit**

- `google_key/` and `shiny/adjudication_app/google_credentials.json` are present
  in the working tree and gitignored. They have never been committed
  (`git log --all -- …` is empty), but they will be captured by any copy or
  archive of the folder. Treat both as live credentials.
